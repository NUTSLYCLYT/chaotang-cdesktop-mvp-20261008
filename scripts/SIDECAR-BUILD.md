# Windows backend candidate

The desktop launcher packages the existing FastAPI service from an exact Git
commit. It does not change backend business code or replace its approval gates.

Use the verified Python 3.12 runtime environment and a separate build-tool
directory. The validated tools were PyInstaller 6.22.3 and hatchling 1.29.0;
`build-evidence.json` records the full actual tool/runtime inventory. The current
backend runtime lock targets Linux: a successful Windows probe is **not** a
Windows lock attestation or release approval.

```powershell
& $RuntimePython scripts/build-chaotang-sidecar.py `
  --backend-repo $BackendRepo --commit $FullCommitId `
  --build-root $NewBuildDirectory --tool-site $BuildToolDirectory

& $RuntimePython scripts/verify-chaotang-sidecar.py `
  --build-root $NewBuildDirectory --probe-root $NewProbeDirectory
```

Both output directories must be new. The builder exports tracked application,
configuration and project metadata from the specified commit. Local databases,
untracked files and local environment files are not source inputs. The backend
wheel metadata is generated by its real build backend. The resulting executable
binds only to loopback, using `CHAOTANG_BACKEND_PORT` (default 8000).

The probe verifies artifact hashes, copies the artifact, disables the task
worker, removes inherited model credentials, and launches without a console
window. It exercises health, anonymous denial, registration, duplicate identity,
wrong password, authenticated identity, process restart, session revocation and
login again using disposable data. It closes its processes and records failures.
It never drives the desktop window or calls a model.

After successful review, copy `dist/chaotang-backend` into
`crates/tauri-app/resources/chaotang-backend` for the Tauri build. Keep any previous
resource directory as a separate backup first. Generated binaries are ignored by
Git; retain the source commit, build evidence and artifact hashes separately.
Do not copy the probe runtime: it contains disposable account data.

Rollback: keep the previous installer and its resource directory; restore that
resource directory for a rebuild or revert this scoped source increment. Do not
delete user databases. This work does not implement installation upgrades, sign
an installer, prove UI flows, or validate real multi-agent execution. Those are
separate release gates.

Reference: [PyInstaller usage](https://pyinstaller.org/en/stable/usage.html).
